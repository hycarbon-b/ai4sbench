## 首次核对时已实施的规则

1. `ProposalSubmission.domain` 和 `Proposal.domain` 继续使用逗号分隔的有序字符串。Website 显式选择主领域并序列化在第一位；历史数据不改写。`field_name` 属于第一个领域，`Proposal.field` 存其 slug。
2. 后台的 PR 指南取第一个领域并转成 slug，生成 `tasks/<primary-domain>/<field>/<task-slug>/`。例如主领域为 `Physics` 时，目录使用 `physics`；其余领域保留在提案中，但不进入目录。此规则解决了把完整逗号列表直接放进路径的问题。
3. 表单选项仍为 `Materials Science`、`Physics`、`Chemistry`、`Biology`、`AI / ML`、`Applied Mathematics`、`Interdisciplinary`。`field_name` 是自由文本，后台按现有规则生成 slug；目前没有发布有限的 `<domain>/<field>` 配对清单，也没有在 API 入口校验领域必须来自这七项。
4. Benchmark 的 `scripts/validate_task.py` 要求五个任务文件、可解析的 `[metadata]` 表；存在 `[task]` 时要求其 `name` 是 `org/name`。新任务 PR 须链接本仓库的提案 Discussion。该校验器**不**检查领域是否属于表单选项，也不强制 `[metadata].domain` 或 `[metadata].field`。

**已确定的范围口径：**当前七个表单标签就是新提案的准入领域；让 AI review rubric 跟随表单，而不是用 rubric 原有的五类科学范围替换表单。`AI / ML` 和 `Interdisciplinary` 也属于这七项，但仍须满足 rubric 对真实研究工作、领域知识、可验证性的其他要求。地球或工程科学如果不能真实归入这七项之一，目前不作为新的独立准入领域。rubric 文字、例子和实际审查行为尚需在后续分支落实；在落实前，不应声称 #46 已由代码解决。

由当前七项按后台现有 slug 规则生成的**新任务主领域目录**为 `materials-science`、`physics`、`chemistry`、`biology`、`ai-ml`、`applied-mathematics`、`interdisciplinary`。这不是对历史目录的迁移要求，例如已有 `mathematical-sciences/applied-mathematics` 示例仍保留。新提案的研究 field 继续由自由文本生成 slug，不能把它误写为现已存在的有限 field 清单。

**已确定的 metadata 口径：**新任务只使用 `[metadata].domain` 与 `[metadata].field` 表达目录分类，分别与任务路径的两个目录段一致；不再为新任务生成或校验 `[metadata].category`。例如 `tasks/physics/inverse-problems/<task-slug>/task.toml` 应包含：

```toml
[metadata]
domain = "physics"
field = "inverse-problems"
```

现有示例的 `category` 是旧写法，后续分支会把示例改成这两个键。旧任务无需因该文档决定而批量改写；校验器新增强制规则时只对**新任务**要求两个键，避免维修历史任务时意外阻断。

## `category` 与 `domain` / `field` 的实际用途

`[metadata].category` 用一个字符串表达两层目录，例如 `mathematical-sciences/applied-mathematics`。在本项目当前代码中，它只出现在 benchmark 示例任务的 `task.toml` 和 Website 的测试样例；任务运行、后台及 benchmark CI 没有依据它进行分类或校验。新的规范不使用这个键。

Website 指南的模板已经使用两个独立键：`[metadata].domain` 对应 `<domain>` 目录，`[metadata].field` 对应 `<field>` 目录。Website 预检在这两个键存在时逐项比对目录，不一致时给**警告**；benchmark CI 尚未要求这两个键，也不检查 `category`。后续分支将把新任务的两个字段及其目录一致性纳入 CI，并使预检保持一致。

GitHub Discussion 的 `category = Task Proposals` 是 Discussion 所在的 GitHub 分类，与 `task.toml` 的 `[metadata].category` 无关。
